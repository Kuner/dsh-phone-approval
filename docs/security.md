# 安全说明

本插件为 DSH 的权限审批增加了一个远程入口。本文说明这个入口如何认证、对哪些网络开放、哪些数据会离开本机，以及已知的限制。

## 设计原则

- **批准必须经过 Face ID 验证。** 手机端的“批准”和“提交回答”都要求 WebAuthn 用户验证；“拒绝”不需要验证，因为它只会让操作不执行。
- **出错时按拒绝处理。** 插件内部出现异常时，DSH 的审批服务会把结果记为 `unavailable`，按拒绝处理。插件不会替用户批准任何请求。
- **不改变 DSH 的授权模型。** 插件只是 DSH 审批流程中的一个应答方，每次批准只对当前这一次请求有效，不保存“始终允许”之类的规则。
- **不开放公网入口。** 所有服务只监听 `127.0.0.1`，审批页通过 Tailscale 发布到私有网络。

## 网络暴露面

| 服务 | 监听地址 | 可访问范围 | 认证方式 |
|---|---|---|---|
| 手机审批页 | `127.0.0.1:47391` | 本机，以及经 `tailscale serve` 转发后 tailnet 内的设备 | 一次性链接 + 批准时 WebAuthn |
| 设置页管理接口 | `127.0.0.1:47392` | 仅本机 | Bearer 令牌 |

插件使用 `tailscale serve`（仅 tailnet 内可访问），不使用 `tailscale funnel`（公网可访问）。TLS 由 Tailscale 终止，证书来自 Tailscale 为 MagicDNS 域名签发的证书。

tailnet 中的所有设备都能访问审批页。如果 tailnet 中有其他人的设备，他们在拿到链接后可以查看审批内容，也可以拒绝请求，但没有你的通行密钥，无法批准。可以通过 Tailscale ACL 限制访问 Mac 8443 端口的设备。

## 审批链接

- 每个请求生成一个 256 位随机 token，链接形如 `https://<host>:8443/a/<token>`。
- 审批链接默认 10 分钟过期，提问链接默认 6 小时过期。请求处理完成、被取消或 DSH 重启后，链接立即失效。
- 处理结果保留 10 分钟，用于在页面上显示“已批准”“已在电脑上处理”等状态，之后清除。
- 所有写操作（注册、批准、拒绝、回答）都会校验 `Origin` 请求头，必须与审批页地址的来源一致。
- 请求体大小上限为 64 KB。回答中的选项必须是题目提供的选项，自定义文本不超过 2000 字符。
- 响应头包含严格的 Content-Security-Policy（`default-src 'none'`、`connect-src 'self'`、`frame-ancestors 'none'`），以及 `Cache-Control: no-store`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`。

## Face ID（WebAuthn）

插件自行实现了 WebAuthn 校验，没有第三方依赖，代码在 `webauthn.js`。

**注册**

- 只接受 ES256（P-256）密钥，不校验证明（attestation 为 `none`）。
- 校验 `clientDataJSON` 中的类型、challenge、origin，拒绝跨域调用。
- 校验 RP ID 哈希、用户在场（UP）和用户验证（UV）标志。

**批准和提交回答**

- 校验凭据 ID、challenge、origin、RP ID 哈希、UP 和 UV 标志，并用已注册的公钥验证签名。
- 每次校验后立即更换 challenge，无论校验是否成功。截获的断言无法重放。
- 签名计数器不为 0 时，必须严格递增。iCloud 钥匙串同步的通行密钥计数器恒为 0，此时不做这项检查。
- 同一个链接连续 5 次校验失败后作废。

通行密钥绑定审批页的域名（RP ID）。域名变化后，原有的通行密钥不再有效。

### 首次注册

只有在当前域名下还没有已注册的通行密钥时，才允许注册；注册入口就是审批链接本身。这意味着首次注册以“谁先完成注册”为准：在你注册之前，任何能打开有效审批链接的 tailnet 设备都可以抢先注册自己的通行密钥。

为降低风险：

- 安装后尽快在自己的手机上完成注册。
- 在设置页确认 Face ID 的注册时间与你的操作一致。如有疑问，点击 **重置** 后重新注册。

## 设置页管理接口

- 只监听 `127.0.0.1`，不经 Tailscale 转发。
- 每个 DSH 进程启动时生成一个 256 位随机令牌，请求必须携带 `Authorization: Bearer <token>`，比较时使用常数时间比较。
- 令牌通过 DSH Web 服务器的页面注入机制下发，只注入给 owner 身份渲染的页面，以只读方式共享会话的其他人拿不到。
- 接口允许跨域请求（设置页与接口端口不同，所以需要），其他网页因为没有令牌，无法调用。
- 写入配置前逐字段校验类型和取值范围，只接受已知字段。

## 数据流向

下表列出每类数据会经过哪些第三方。

| 数据 | 公共 Bark 服务器（未加密） | 公共 Bark 服务器（已加密） | 自建 bark-server | Apple 推送服务 |
|---|---|---|---|---|
| 设备 key | 可见 | 可见 | 仅本机 | 不可见 |
| 会话标题、工具名 | 可见 | 不可见 | 仅本机 | 未加密时可见 |
| 审批原因、问题、回复预览（`includeDetails` 开启时） | 可见 | 不可见 | 仅本机 | 未加密时可见 |
| 审批链接 | 可见 | 不可见 | 仅本机 | 未加密时可见 |
| 将要执行的命令 | 不发送 | 不发送 | 不发送 | 不发送 |

说明：

- 将要执行的命令和工具参数只显示在审批页上，从不写入推送。
- 自建 bark-server 默认会把请求体写入容器日志。未开启加密时，日志中有推送明文。
- 审批链接只在 tailnet 内可以打开，批准还需要 Face ID，因此链接泄露本身不足以批准请求。

## 推送加密

- 使用 Bark 的加密格式：AES-256-CBC，PKCS#7 填充，密文以 Base64 编码。
- 每条推送生成新的随机 IV，并随密文一起发送。
- 标题、正文、分组、通知级别、链接全部放在密文中，明文字段只剩设备 key 和 IV。
- 读取加密设置失败时，推送直接放弃，不会退回明文发送。
- 新生成的密钥默认不启用。确认手机能解密后，再手动启用。

CBC 模式不提供完整性校验，这是 Bark 加密格式本身的限制。加密能阻止中间方读取推送内容，但不能防止密文被篡改。审批的安全性不依赖推送内容：即使链接被篡改，最多导致页面打不开。

## 本地存储

| 数据 | 位置 |
|---|---|
| Bark key、通行密钥公钥、加密密钥 | `~/.dsh/.credentials.yaml`（DSH 凭据存储，文件权限 600） |
| 插件配置 | DSH profile 的 `cordis.patch.yml`，不含密钥 |
| 待处理请求和链接 | 仅在内存中，DSH 退出后清空 |

插件作为 DSH 的 Host 插件运行在 DSH 主进程中，权限与当前用户相同，不受 agent 沙箱限制。

## 已知限制

- 首次注册以“谁先完成注册”为准，见[首次注册](#首次注册)。
- tailnet 内的设备拿到链接后可以拒绝请求。
- 手机处理后电脑端对话框自动关闭，这一点依赖 DSH 内部会读取审批请求上的取消信号（`request.signal`）。这不是 DSH 公开承诺的接口，DSH 升级后可能失效。失效时电脑端对话框不会关闭，但审批结果不受影响，仍以先给出的决定为准。
- DSH 会话日志中的 `approval/decided` 只记录结果，不区分是在手机还是电脑上处理的。插件会在 DSH 运行日志中记录手机端的处理结果。

## 报告问题

发现安全问题时，请通过仓库的 issue 联系维护者，不要在 issue 中附带真实的审批链接或密钥。
